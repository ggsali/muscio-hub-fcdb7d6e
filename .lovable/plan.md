
## Problem Identified

The `supabase.storage.uploadToSignedUrl()` method internally prepends the Supabase Storage base URL and uses the token as a path parameter — but the presign endpoint already returns the **full signed URL** (`signedUrl`) with the token embedded as a query param. The client method is being called with `presignData.storagePath` + `presignData.token` which constructs a *different* URL internally, causing a mismatch/auth error leading to "Verbindungsfehler".

The fix is to **upload directly via `fetch` PUT** to `presignData.signedUrl` (the full URL already containing the auth token as `?token=...`). This is the correct approach for signed upload URLs from Supabase Storage.

For progress tracking on large files, use `XMLHttpRequest` with the `upload.onprogress` event.

## Changes

**`src/pages/ProjectUploadPage.tsx`** — Replace the `uploadToSignedUrl` call with a direct `XMLHttpRequest` PUT to `presignData.signedUrl`:

```typescript
// Instead of:
const { error: uploadError } = await supabase.storage
  .from("project-uploads")
  .uploadToSignedUrl(presignData.storagePath, presignData.token, file, {...});

// Use direct PUT to the full signed URL with XHR for progress:
await new Promise((resolve, reject) => {
  const xhr = new XMLHttpRequest();
  xhr.upload.onprogress = (e) => {
    if (e.lengthComputable) {
      const pct = 30 + Math.round((e.loaded / e.total) * 50);
      updateFile({ progress: pct });
    }
  };
  xhr.onload = () => xhr.status >= 200 && xhr.status < 300 ? resolve(null) : reject(new Error(`HTTP ${xhr.status}`));
  xhr.onerror = () => reject(new Error("Netzwerkfehler"));
  xhr.open("PUT", presignData.signedUrl);
  xhr.setRequestHeader("Content-Type", file.type || "application/octet-stream");
  xhr.send(file);
});
```

This approach:
- Uses the exact signed URL returned by the backend (no URL reconstruction)
- Provides real-time progress percentage (30%→80% during upload)
- Works for files of any size (no limits)
- No CORS issue since the signed URL is generated by Supabase Storage specifically for direct browser uploads
